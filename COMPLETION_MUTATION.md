# Completion mutation v1

[PWA natural-completion admission](PWA_NATURAL_COMPLETION.md) extends centralized PWA Finish admission to exact completed timers whose last intent is Start or Resume. It defines once-only lifecycle consumption, explicit selection, and the required history evidence.

`workspace.completionMutation.v1` plans completion mutations without persisting state. Apple, Android, and PWA centralized finish stages retain their Finish and optional generated Start batch. Apple Iroh manual Finish and Desktop centralized Finish now produce a separate break opportunity. [Staged completion lifecycle v1](COMPLETION_LIFECYCLE.md) defines `expiryObservation`, `deferredBreakOpportunity`, their complete schema, and their transaction boundaries. No client calls this operation yet.

## Request

The request uses the `workspace.intent.v1` fields documented in `WORKSPACE_INTENT.md`, except `intent` is replaced by `stage`. It requires `requestedTimer` and an explicit `ownership` field. `ownership` is null or an object with `timerId` and `deviceId`; optional `tabId` and `leaseExpiresAtMs` retain PWA lease context. A caller passes the timer it presented to the user, not a projected timer or a proposed finish. The `workspace` contains the raw canonical base, all five retained queues, `canonicalHead`, `neverSent`, and `timerDependencies`. The caller must not supply `workspace.now`; Core sets projection times. The caller supplies `calendarIntervals`, physical observations, selection, allocation state, one or two unused command UUIDv7 candidates, and either a raw UUIDv4 timer candidate or `null`.

Centralized finish batches use `replicationMode: "centralized"`. Apple Iroh manual Finish is also supported. Desktop manual or automatic Finish now retains a deferred trigger instead of appending Start. A canonical base timer with embedded `dependsOnCommandId` requires another stage; retained dependencies use the `timerDependencies` graph. An optional presented `dependsOnCommandId` must match its retained parent. The caller must not replace the canonical base with its display projection. `clock.observedAt` is the elapsed observation used to build the finish command. `clock.physicalNow` is the physical time for command replay; `clock.occurredAt` is the trusted time for the wire command. The PWA profile accepts the raw monotonic clock fields and saved anchor described in `WORKSPACE_INTENT.md`.

## Automatic finish request

Set `stage: "automaticFinishCommit"`. Supply a presented running timer and the same raw workspace, allocation, identities, clock, and observation as for manual finish. Core recomputes the fresh unexpired timer from the canonical base and all five retained queues. It then projects expiry at `clock.observedAt` (PWA uses raw monotonic sample and continuity when supplied). Core compares the complete presented fingerprint including `lastIntent`, requires a running-to-completed transition, and rejects a prior finish. A paused timer, stale snapshot, or early clock returns `noop`. The exact expiry boundary can plan a finish. Manual `finishCommit` still bypasses owner and expiry checks.

`ownership` supplies the raw local owner record for Apple and Android: `{timerId, deviceId}`. Apple falls back to canonical `startedByDeviceId` only when the record is absent; Android requires the local owned-timer record. PWA supplies the persisted owner record with `tabId` and optional `leaseExpiresAtMs`, plus `localTabId` and `leaseNowMs` (raw local clock, separate from trusted timer time). Same-device same-tab owns even while the lease is live. Same-device foreign tab owns at or after lease expiry, or when the lease is missing. Missing PWA owner can be claimed if canonical `startedByDeviceId` matches the local device. If canonical owner attribution is missing, **any** retained Start for this timer permits the PWA claim, including a foreign-device Start. This preserves current IndexedDB behavior; it is not evidence of same-device origin. An existing foreign-device owner record never grants ownership merely through lease expiry. PWA owner denial returns `noop` with `reason: "not_owner"`; Apple and Android use `notOwner`. PWA returns `retryAtMs` only for a live same-device peer-tab lease; otherwise the key is absent. PWA's current retry handler treats absent `retryAtMs` as a heartbeat retry, whereas explicit `null` produces a 250 ms retry.

Auto-start follows Core's projected setting across all five retained queues. Supply two increasing UUIDv7 candidates in `identities.commandUuids` and a UUIDv4 `identities.timerUuid` when a generated start is possible. Finish uses candidate 0; generated Start uses candidate 1 and `timerUuid` (`timer-` prefix on Apple). Unused valid candidates do not advance `allocation.lastUuid`, sequence, or HLC beyond commands actually planned. For PWA generated starts, supply `localTabId`, `leaseNowMs`, and positive JavaScript-safe `leaseDurationMs`; Core checks their sum. The request accepts no caller `ownerGranted`, `ownsTimer`, `automatic`, or proposed projection fields. Noop spends no UUID, advances no HLC or sequence, writes no ownership, and returns no effects. Run `effectsAfterCommit` only after successful persistence; an error or noop writes nothing.

Apple's 10 ms millisecond-boundary retry is optional `boundaryRetry: {originalObservedAt, measuredElapsedMs}` on `automaticFinishCommit`. Pass the original physical observation as `originalObservedAt` and its single compensated observation, exactly 10 ms later, as `clock.observedAt`. `measuredElapsedMs` must reach presented duration; original observation must not exceed `physicalNow`. Without this evidence, a future observation fails. Core does not allocate during an early/noop attempt.

## Result

The result contains `schemaVersion: 1`, `outcome`, `reason`, `workspace`, `projection`, `selection`, `allocation`, `observation`, `commands`, `durableCommands`, `atomicCommandIds`, `completionRecords`, `ownershipWrites`, and `effectsAfterCommit`. `commands` and `workspace.local.commands` contain `deviceId` for Core projection. `durableCommands` contains the platform's persisted command shape. Apple, Android, and Desktop omit `deviceId` in that shape; PWA retains it. Desktop uses a millisecond RFC 3339 `occurredAt` value. Android's transient physical occurrence is returned in `observation.commandTimes`, not in its wire payload. PWA persists `dependsOnCommandId` and `generatedBreak: true` on generated Start. Android and Apple persist plain commands and a separate `workspace.timerDependencies` edge. A follow-up command on a retained generated break depends on the latest retained command for that timer, ordered by HLC, device, and ID. It does not inherit the focus Finish as parent. PWA also persists this direct parent's ID in the follow-up finish command.

On `planned`, `atomicCommandIds` contains one finish ID or ordered Finish+Start IDs. The updated `workspace` appends commands and never-sent proofs atomically; it retains other queues and canonical base. A generated dependency has `operationId`, `dependsOnOperationId`, `generatedBreak: true`, `sourceDayStart`, and `sourceDayEnd`. `projection` is the safe Core workspace projection after the batch, not a new canonical base. Core requires an applied finish outcome and a completed history row with the exact timer, command, and phase before deriving phase with `timer.completionPlan.v1`; it requires generated Start to apply too. Focus counts 4 and 8 in supplied calendar day select a long break. Generated duration comes from projected pending settings. Apple records a provisional phase advance unless selection is explicit and records `completionRecords.provisionalBreak` with focus timer, finish command, break timer, and start command identities. Apple's provisional break is held from delivery until its finish source is accepted; both commands and provisional record share existing `commitSynchronizedState` boundary. Android increments its generation only when phase changes, retains a separate dependency map, and sets its owned timer ID to generated timer. PWA retains its generation and replaces owner with generated break lease (`ownershipWrites: [{kind: "recordTimerOwner", timerId, deviceId, tabId, leaseExpiresAtMs}]`). Without generated Start, PWA returns `removeTimerOwner`. Effects are `launchSync`, `cancelAlarm` for finished timer, then `scheduleAlarm` for generated break; schedule only after commit.

On `noop`, `reason` is `staleTimer` for a stale snapshot; automatic expiry can also return `notExpired` or an owner denial (`not_owner` on PWA, `notOwner` on Apple/Android). No command, ownership write, completion record, or effect is returned. The workspace, selection, allocation, and observation remain unchanged. Core compares the presented timer's ID, status, phase, duration, anchor, elapsed value, task ID, and complete last intent with the fresh projection. The last-intent comparison includes type, command ID, and raw occurrence time. A different ownership timer ID cannot block manual finish; it denies automatic finish. Invalid JSON, `workspace.now`, allocation, clock, calendar, queued domain, proof, and dependency contexts fail with an error instead of producing a plan.

The caller must read the transaction snapshot under its account gate and lock. On `planned`, it persists returned queues, proof, dependency graph, selection, allocation, observation, durable command payloads, completion records, and ownership write atomically. It executes effects only after commit. On `noop` or error, it persists nothing. Apple retains local physical command dates and provisional break in persisted state. Desktop persists its phase-advance row and command without `deviceId`; it normalizes retained commands with device identity when preparing later Core request. Android retains physical occurrence metadata separately. PWA owner replacement/removal belongs in same IndexedDB transaction as both commands and proof. Planner does not move any client's transaction boundary. Apple Iroh Finish and follow-up Start use separate stage calls and commits. Desktop Finish and its deferred opportunity also remain separate commits, as specified in `COMPLETION_LIFECYCLE.md`.

`reconcile.rebase.v2` normalizes the generated break batch after the exact focus Finish acknowledgement, but promotes only the generated Start. It retains the follow-up edge while Start is unacknowledged. An applied Start acknowledgement promotes the direct child once; a rejected Start drops the unsent descendant. An unrelated acknowledgement does not release the child. A sent or otherwise possibly delivered command remains immutable; adapters preserve never-sent proof separately. PWA rebuilds command dependency fields from `pendingTimerDependencies` when persisting a reconciliation result.

Production source parity is limited by unchanged clients. Apple's `coreTimerDependencies` chains break commands through the generated Start. PWA's `finishTimerCommand` copies the generated timer's focus-Finish parent. Android's `dependencyForTimer` returns the generated Start's parent. Both therefore produce a sibling edge to focus Finish, not the required edge to generated Start. `scripts/completion_followup_source_probe.py` executes all three production methods and reports this divergence. A client adapter must later persist Core's direct edge before this planner can replace those existing follow-up flows. This Core-only change does not claim PWA or Android follow-up source parity.

## Verification scope

`tests/completion_mutation.rs` keeps existing finish and owner vectors. `tests/completion_generated_break.rs` uses `fixtures/completion-generated-break-v1.json` for focus counts 3/4/7/8, both finish stages, break finish, pending setting overrides, direct dependency inheritance, duplicate retry, denial, identity and clock overflow, Apple 10 ms retry, and two-step reconciliation. The latter tests focus Finish applied before Start, Start rejected or applied, unrelated acknowledgement barriers, batch delivery selection, and once-only promotion for PWA, Android, and Apple Core profiles. `scripts/completion_mutation_source_probe.py` executes extracted Apple and Android production generated-start builders and Android's separate dependency map, plus four full production PWA fake IndexedDB Finish+Start transactions with existing bundled Shared Core. It compares exact commands, selection, owner lease, sequence, HLC, and UUID cursor to native Core. `scripts/completion_followup_source_probe.py` reports Apple parity and PWA/Android divergence for follow-up edges. Probes do not verify alarms, deployment, packaged planner WASM, or client adoption. Android's extracted `canFinishTimer` uses system time, so deterministic exact-boundary parity rests on Core tests rather than that method probe. PWA legacy non-UUIDv7 allocation remains unsupported. `COMPLETION_LIFECYCLE.md` describes the additional Iroh and Desktop stage evidence and remaining migration blockers.

Native verification uses pinned Rust 1.97.1, format, warning-denying Clippy, and all-target tests with the two named WASM-building tests filtered. No bundled WASM artifact or client adapter is changed by this stage.
## Durable admission extension

The [durable intent admission reference](DURABLE_INTENT_ADMISSION.md) describes the
later shared admission rule. Completion results now include `commandOutcomes`
with `applied` or `queued` display status. Exact completion provenance is checked
in the complete retained ledger. The returned projection remains delivery-safe.
